Confidence: high — the 8x8 mapping is pinned by three independent evidence classes that agree (official Hevy help/feature pages, the live built-in exercise-template catalog dumped from GET /v1/exercise_templates by multiple unrelated repos, and client code with live-verified comments documenting the POST→GET alias); the only part not executed first-hand is the POST-side alias, which rests on a live-verified third-party code comment plus the total absence of the documented spellings in all readback data.

# Hevy exercise-type mapping — verified

## Headline result

The prior inference is CONFIRMED: the API enum value `bodyweight_reps` means **bodyweight WITH added weight** (UI "Weighted bodyweight"), and the UI's "Bodyweight reps" (plain pull-ups/push-ups) is the API's `reps_only`. Additionally, the API has **two vocabularies**: the 8-value `CustomExerciseType` enum accepted on **create** (POST /v1/exercise_templates), and a **10-value** set of type strings returned on **read** (GET /v1/exercise_templates). Two values are rewritten between them, and two extra types exist only on built-ins.

**Wire aliasing (create → readback)** — from chrstnwhlrt/hevy-app-mcp-rs `src/hevy/models/common.rs`, comment marked "live-verified 2026-04-21": "Hevy aliases two of these on readback: `bodyweight_reps` (POST) → `bodyweight_weighted` (GET response); `bodyweight_assisted_reps` (POST) → `bodyweight_assisted` (GET response)". The same file notes the server rejects any other create value "with an explicit Zod enum error listing exactly these variants" (the 8 documented ones), and that the catalogue emits a strictly broader set on read, including `floors_duration`/`steps_duration` on built-ins. Corroborated by mukulkatewa/kak_fit `packages/db/scripts/hevy/mappings.ts` ("Live API types (OpenAPI enum is outdated — e.g. bodyweight_assisted vs bodyweight_assisted_reps)") and by benjaminshafii/digital-empire `API-TESTING-METHODOLOGY.md`, which extracted all unique types from a live 435-template GET (2025-10-22) and explicitly flags `bodyweight_reps` as "Doesn't exist!" in readback data.

## Evidence for the two ambiguous pairs

Live built-in catalog (two independent dumps of GET /v1/exercise_templates — khoiphan21/workout-routines cache fetched 2026-06-18 with 488 templates = 433 built-in + 55 custom, and aunefyren/treningheten with the identical 433 built-ins):

- `Pull Up (Assisted)`, `Pull Up (Band)`, `Chin Up (Assisted)`, `Chest Dip (Assisted)`, `Triceps Dip (Assisted)` → all `bodyweight_assisted` (6 built-ins).
- Real user custom exercises in the June-2026 dump read back ONLY as: `reps_only` (26), `weight_reps` (15), `duration` (11), `bodyweight_weighted` (2 — titled "Weighted Dip", "Bar Muscle Up"), `bodyweight_assisted` (1 — "Band-assisted High Pull-Up"). ## Where added/assistance weight is stored

The Set object has exactly one weight field, `weight_kg` (spec: Set schema fields are index, type [normal/warmup/dropset/failure], weight_kg, reps, distance_meters, duration_seconds, rpe [enum 6,7,7.5,8,8.5,9,9.5,10], custom_metric). So:
- **Weighted bodyweight**: `weight_kg` holds ONLY the added external load (e.g. +10 kg on a weighted pull-up), NOT bodyweight. JunAkerBuilds/CorosLink `electron/hevyModel.ts`: bodyweight variants "may carry explicit added weight, which is safe to preserve as external load"; wathmal/workout-sync `lib/hevy/catalog.ts`: "`bodyweight_weighted` (e.g. Weighted Pull-Up, Sit Up (Weighted)) accepts weight_kg + reps, identical to weight_reps for sync purposes."
- **Assisted bodyweight**: `weight_kg` holds the assistance amount. CorosLink zeroes it on import ("Assisted weight is assistance, not load lifted"); Poshy163/gym-discord-bot docs/HEVY.md: "the logged kg is read as machine assistance (true load = bodyweight − assistance)" and warns that confusing the two turns a +20 kg weighted pull-up into a 40 kg error — disambiguation is ONLY possible via the template's `type` (`bodyweight_weighted` vs `bodyweight_assisted`), not the set data.
- **Bodyweight itself is never stored in sets.** Official help article "Bodyweight Exercises in Hevy" (fetched via the Zendesk API): the app pulls bodyweight from Measurements (or "Update Bodyweight" on the exercise's three-dot menu during a workout). Volume math, quoted: bodyweight — "each rep counts your bodyweight toward the workout's total volume" (10 reps x 100 kg = 1000 kg), but ONLY for specific library exercises "that use 100 percent of bodyweight": Pull up, Chin up, Dips, Handstand push ups; assisted — "Effective load = bodyweight − assistance"; weighted — "Effective load = bodyweight + added weight". Critical clone-relevant caveat, quoted: "If you create a bodyweight exercise (bodyweight, assisted, or weighted) as a custom exercise, it will not add your bodyweight to the total volume." Per-type PRs from the same article: bodyweight → best sets + most session reps; assisted → most reps (set) + best total reps; weighted → best set volume + heaviest weight.

## Which types show a weight column (official)

hevycoach.com workout-builder FAQ, quoted: "Any exercise that's classified as Weight Reps, Weighted Bodyweight, Assisted Bodyweight, or Weight & Distance (in our library or a custom one you've created) comes with a KG or LBS section, where you can provide a weight target for each set." ("Duration & weight" is not named in that FAQ sentence but carries weight by definition and by its `weight_duration` field pairing.) hevyapp.com how-to-write-sets-and-reps: KG/LBS column + REPS column for weight-and-reps exercises; "Duration-based activities like planks come with a single TIME column."

## Other clone-relevant facts picked up en route

- ExerciseTemplate schema (spec): id, title, type, primary_muscle_group, secondary_muscle_groups, equipment_category, is_custom. Built-in IDs are 8-char hex ("3BC06AD3"); custom-exercise IDs are UUIDs (seen in the dump: "cd92a721-419c-...").
- MuscleGroup enum (20): abdominals, shoulders, biceps, triceps, forearms, quadriceps, hamstrings, calves, glutes, abductors, adductors, lats, upper_back, traps, lower_back, chest, cardio, neck, full_body, other. EquipmentCategory enum (9): none, barbell, dumbbell, kettlebell, machine, plate, resistance_band, suspension, other (spec).
- Set type enum: warmup, normal, failure, dropset; RPE enum: 6, 7, 7.5, 8, 8.5, 9, 9.5, 10 (spec).
- An exercise's type CANNOT be changed after creation — official help article "How to Create Custom Exercises in Hevy", quoted: "You can edit the title, asset..., equipment, primary muscle group and secondary muscles. The type of exercise cannot be changed."
- GET /v1/exercise_templates supports pageSize up to 100 (vs 10 elsewhere); the full built-in catalog was ~435 templates in Oct 2025 and 433 built-ins in the June 2026 dump (benjaminshafii methodology doc + dumps).
- The real OpenAPI spec is NOT at /docs/swagger.json (that path returns the HTML shell); it is inlined as `swaggerDoc` inside https://api.hevyapp.com/docs/swagger-ui-init.js (spec version "0.0.1", title "Hevy API Docs").
